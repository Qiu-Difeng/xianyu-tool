## v1.4.7 — v1.4.7 - 提示词模板 · 队列重试

## 新增：提示词模板

V3 自定义提示词原来每次都要重打，现在可以存起来复用。

**怎么用**

1. 在输入框写下提示词（如「突出性价比和限时优惠，语气活泼」）
2. 点「存为模板」→ 起个名字（如「促销风」）
3. 下次点模板标签即可填充输入框
4. 标签右侧的 × 可以删除

模板存在 `%LOCALAPPDATA%\XianyuTool\prompt_templates.json`，最多 30 条，同名覆盖。

## 新增：队列失败一键重试

批量跑时某几条失败（下载超时、链接失效等），原来只能重新粘贴一遍。

现在队列页有「重试失败」：把失败的条目重置为待处理，点「开始处理」即可重跑。

## 关于「断点续跑」——这次没做，说明原因

完整断点续跑要把主流程的四个阶段（解析/下载/去水印/文案）拆成可跳过的独立步骤，还要处理目录状态判定。

但实测数据说明价值有限：

| 阶段 | 耗时 | 失败后重跑代价 |
|------|------|---------------|
| 解析 | 15 秒 | 多花 15 秒，可以接受 |
| 下载 | 0.4 秒 | 几乎无感 |
| 去水印 | 8-14 秒 | 可以接受 |

而真实的失败场景里：

- **解析失败**多为链接无效 → 重跑还是失败，续跑没意义
- **下载失败**多为网络抖动 → 整体重跑反而更干净
- **文案失败**（最常见）→ 已有单版本重试按钮

所以本次只做了队列级重试。如果以后你确实遇到"跑到一半失败要重来很痛苦"的具体场景，再针对性做。

## 修复：拆分代码时漏掉的闭合括号（重要）

上一版拆分 `workflow.js` 时，区间写成 `1758-2310`，漏了第 2311 行的 `});`——那是 `window.addEventListener('pywebviewready', () => {` 的闭合。

**后果很隐蔽**：`});` 被算进模板尾部跑到文件最末尾，导致这个箭头函数把后面所有代码都包了进去。语法**完全合法**（`node --check` 通过），但新加的函数在全局访问不到，报 `loadPromptTemplates is not defined`。

这类"语法合法但作用域错了"的 bug 所有静态检查都查不出来，只能靠运行时发现。

```
ui/dialogs.js    216 行   日志 / 引导 / 反馈
ui/workflow.js   554 行   主流程与渲染
ui/index.html    230 行   模板
```

`build_ui.py` 合并，已集成进 `XianyuTool.spec`（打包前自动执行）。

**验证**：合并产物与拆分前逐行比对，差异仅 1 行（主动丢弃的一处错位残留注释）。运行时 14 个函数可调用、4 个弹窗正常、队列渲染正常。

## v1.4.3 — v1.4.3 - 处理提速 35% · 批量文案修复

## ⚡ 处理提速 35%：37.1 秒 → 24.2 秒

用真实链接实测了完整流程，拿到分段耗时——**数据推翻了我之前的判断**：

```
模块1_解析      26.9 秒   ← 占 72%，不是我以为的去水印
模块2_下载图片   0.7 秒
模块3a_去水印     8.3 秒   ← 只有 22%
模块3b_文案       后台异步
```

**瓶颈在「解析」**，其中一大半耗在拟人化防封动作用。

### 改了什么

`anti_detect` 里的拟人动作：

```python
# 改前：滚 3-6 次，每次 0.5-1.5 秒；鼠标动 2-5 次，每次 0.2-0.8 秒
# 合计 2.9-15 秒，平均约 9 秒
# 改后：滚 2-3 次，每次 0.25-0.6 秒；鼠标动 1-2 次，每次 0.15-0.35 秒
# 合计 1.2-3.2 秒
```

**保留了全部动作和随机性**——反检测的关键是「有随机的滚动和鼠标行为」，而不是「每个动作持续时间长」。限流间隔也同步从 2-5 秒降到 1.5-3 秒。

**实测结果**：

| 阶段 | 改前 | 改后 |
|------|------|------|
| 解析 | 26.9 秒 | **15.5 秒** |
| 下载 | 0.7 秒 | 0.4 秒 |
| 去水印 | 8.3 秒 | 8.3 秒 |
| **主流程合计** | **37.1 秒** | **24.2 秒** |

10 条批量从原来的约 6 分钟降到 **约 5 分钟**（含批间停顿）。

## 🐛 修复：批量任务的文案会互相拖死

文案是后台异步线程生成的。批量队列连续跑的时候：

```
第1条跑完 → 留下 1 个文案线程还在调 AI
第2条跑完 → 又留下 1 个
...
10 条跑完 → 10 个线程同时请求同一个模型接口
```

免费额度很容易被打到限流，**结果是文案大面积失败**——这个比「慢」严重得多。

**处理方式**：

1. 加 `Semaphore(2)`，同时最多 2 条文案在生成，其余排队
2. 队列**不等文案**：实测文案耗时刻在 10 秒到 120 秒之间剧烈波动（免费模型排队），等它会把单条从 24 秒拖到 140 秒。改为主流程不等，文案后台补齐，界面刷新即可看到

实测验证：主流程 24.2 秒返回，文案 5 秒后补齐，三版齐全（314/301/332 字）并写入 `result.json`。

## 🔧 顺带修复

`xianyu_tool.py` 缺 `import threading`（原来只在函数内部 import），
导致模块级新增的 `_COPY_SEMAPHORE` 一定义就报 `NameError`，整个程序起不来。
已补上并验证模块可正常导入。

## 📦 说明

- 上一版（1.4.2）的批量队列功能不变，只是更快更稳
- 文案生成的等待策略：单条处理不等（界面异步展示），批量也不等（后台补齐）
- 如果模型排队严重导致文案很慢，可以在「Key 配置」里换成响应更快的模型

## v1.4.2 — v1.4.2 - 批量队列

## 📦 新增：批量处理队列

以前一次只能处理一条链接，跑完再粘下一条。现在有了「批量」标签页：

```
┌─ 批量 ──────────────────────────────────┐
│ 粘贴链接（每行一条，重复与无效行会自动跳过）│
│ ┌─────────────────────────────────────┐ │
│ │ https://m.tb.cn/h.xxxx              │ │
│ │ https://m.tb.cn/h.yyyy              │ │
│ └─────────────────────────────────────┘ │
│ [加入队列] [开始处理] [停止] [清除已完成] │
│                                         │
│ ▓▓▓▓▓▓▓░░░░░  共 7 条  已处理 4/7       │
│ 成功 3  失败 1  进行中 1  等待 2         │
│                                         │
│ ✓ 蓝牙耳机          蓝牙耳机 · 12.3s [打开]│
│ ✗ 失败              模块2_下载图片：超时   │
│ ⟳ 处理中            去水印                │
│ 🔗 排队中          https://m.tb.cn/...   │
└─────────────────────────────────────────┘
```

**执行策略：串行**

一次只跑一条，每条之间自动插入 **3~8 秒随机间隔**。

这是刻意的取舍——闲鱼对同一账号的并发请求很敏感，同时跑多条容易触发验证码甚至临时限流。固定间隔也容易被识别成脚本，所以用随机值。**宁慢勿险。**

按每条 1-2 分钟估算，10 条大约 15-25 分钟。

**修掉一个会导致数据丢失的隐患**

原来 `run()` 一开始就执行 `rmtree(OUTPUT_ROOT/output)` —— 这是"只保留最新一次"的设计。批量跑的时候，**每一条任务都会把前面刚跑完的结果删掉**。

现在改为解析出 `product_id` 后只覆盖自己那一个目录。同一条链接重跑会覆盖自己的旧结果，不影响其他商品。

顺带实现了你要的「历史结果全部保留」：跑过的商品结果都留在 `%TEMP%\xianyu_tool\output\{商品ID}\`，随时能翻回去看。

**冲突保护**

队列和单条处理共用同一个浏览器用户目录，同时跑会出现两个 Chromium 抢同一份 `user_data_dir`，直接卡死。所以做了双向互斥：

- 队列运行中，点单条「开始」会被拒绝并提示先停止队列
- 单条任务运行中，点「开始处理」会被拒绝并提示等它结束

**其它细节**

- 入队自动去重、过滤非链接行，并告诉你「跳过 N 条」
- 成功的条目带「打开」按钮，直接跳到该商品的结果目录
- 轮询只在批量标签页激活时进行（1.5 秒/次），切走就停，不空转

## v1.4.0 — v1.4.0 - 日志落盘 · 异常追踪 · 弹窗重构

## 🔍 出问题终于能查了：日志落盘

之前后端有 **173 处 `print`**，打包成窗口程序后全部被系统吞掉——
用户报「失败了」，你这边什么都看不到，只能靠猜。

现在所有输出自动落盘：

```
%LOCALAPPDATA%\XianyuTool\logs\2026-10-29.log
```

- 按天分文件，自动保留 14 天
- 控制台输出、标准错误、第三方库的打印一并接管
- 跨天自动切新文件，写日志失败绝不打断主流程

**实现方式上做了取舍**：没有逐行改写那 173 处 `print()`（容易引入回归），
而是在 `stdout` 上挂了一层 tee，让输出同时进控制台和文件。零改动、零风险。

遇到问题时，把当天的日志文件发回来就能定位。
程序内也有接口可读取（`get_log_info`），后续会做成界面上的「查看日志」按钮。

## 🎯 失败时告诉你卡在哪一步

原来主流程任何未预期异常都会直接抛给界面，用户只看到一串裸异常文本，
分不清是解析失败、下载失败还是保存失败。

现在主流程按阶段走，出错时明确报出环节：

```
初始化 → 模块1_解析 → 模块2_下载图片 → 模块3a_去水印
       → 模块5_补充图 → 模块6_保存结果
```

报错形如「阶段「模块2_下载图片」失败：…」，完整堆栈同时进日志。

## 🧩 弹窗架构重构

原来 7 个弹窗各自在 JS 里拼一整套内联样式骨架，同一份卡片/按钮/输入框样式
复制了 7 遍，改一次视觉要翻 7 处字符串，深浅色主题也无法统一维护。

现在：

| 指标 | 改造前 | 改造后 |
|------|--------|--------|
| 弹窗内联 `cssText` | 7 个 | **0** |
| 统一的 `.modal-*` 样式类 | 0 | 35 个 |
| 弹窗骨架代码 | 复制 7 份 | **1 份** |

- 新增 `Modal` 工厂：图标 / 标题 / 描述 / 主体 / 按钮组 / 底部说明
- 引导、反馈、更新弹窗全部迁移，按钮事件从内联 `onclick` 改为监听器
- 视觉随主题自动切换，浅色模式下不再出现深色块

## 🔒 安全补丁

发布前审查发现三处渲染路径仍在拼接原始数据（主体数据此前已转义）：

1. `<img src="…">` —— 路径含引号可闭合属性并注入事件
2. 违禁词列表 —— 数据来自 **AI 返回**，属半可信内容
3. 版本标签 —— 程序内部常量，风险低但一并加固

已统一走 `escapeHtml()`。

验证方式：用 `<img src=x onerror=alert(1)>` 和 `a" onerror="alert(2)`
两种载荷真实注入三个路径，确认元素未被创建、内容以纯文本呈现。

## v1.3.7 — v1.3.7 - 界面重做 · 多模型 · 去水印修复

## 🎨 界面重做：三主题 + 全站自绘图标

**1. 深色 / 浅色 / 跟随系统**

顶栏新增主题按钮，点一下循环切换。选「跟随系统」时读 Windows 注册表的
`AppsUseLightTheme`（比浏览器的 `prefers-color-scheme` 可靠），系统切换深浅色时实时跟随。

浅色主题不是简单反色：整套颜色令牌重新调过，去掉了深色下的壁纸和星雪装饰，
输入框、卡片、tab 的对比度都单独校准。

**2. 去掉全部 emoji，换成自绘 SVG**

原来界面里有 **86 个 emoji、31 种**，不同系统/字体下渲染差异很大，
而且 emoji 当图标用不符合基本设计规范。

现在全部换成自建图标集：26 个 SVG symbol，统一 24×24 网格、1.75 描边、
圆头端点、跟随文字颜色（`currentColor`）。页面实测 emoji 数 **0**。

运行日志也不再靠 emoji 表示级别，改用左侧小圆点区分成功/失败/警告。

**3. 修复：引导每次启动都弹**

根因很有意思——pywebview 用 `html=` 直接渲染时，页面地址是 `about:blank`，
浏览器的 localStorage **和** sessionStorage 都会抛
`SecurityError: Access is denied`。之前"用 localStorage 记住引导已看过"的写法
从来没有生效过，"跳过此版本"其实也一直是坏的。

现在界面状态（引导是否看过、主题选择、跳过的版本号）统一存到
`%LOCALAPPDATA%\XianyuTool\ui_state.json`，实测重开不再弹引导。

**4. 顺手修的可读性问题**

- 输入框占位提示原来写死了暖白色，浅色主题下完全看不见
- 未选中的 tab 在浅色下和背景糊在一起
- 补上 `prefers-reduced-motion`，系统开了"减少动效"时关闭动画

## 🤖 支持多家大模型，文本与视觉可分开配

原来模型是写死的：文案固定 `glm-4-flash`，去水印固定 `glm-4v-flash`，客户端只用智谱 SDK。
想换 DeepSeek 或魔搭完全没有入口。

现在新增统一的大模型层，**任何 OpenAI 兼容服务都能接**：

| 服务商 | 文本模型 | 视觉模型（去水印） | 备注 |
|--------|----------|-------------------|------|
| 智谱 AI（推荐） | glm-4-flash | glm-4v-flash | 两个都免费不限量 |
| 魔搭 ModelScope | Qwen2.5-72B-Instruct | Qwen2-VL-7B-Instruct | 有免费额度 |
| DeepSeek | deepseek-chat | — | **不支持图片**，去水印需另配视觉模型 |
| 自定义 | 任意 | 任意 | 填任意兼容 `/chat/completions` 的地址 |

- 配置窗口加了「服务商」下拉，切换时自动填好地址和模型名，只改 Key 就行
- 勾选「高级：文本/视觉分开配」，可以让**文案走 DeepSeek、去水印走智谱**，各用各的 Key
- 单独的「测试文本模型」「测试视觉模型」按钮，配完立刻验证

## 🔑 首次使用只需填一次 Key（图形界面）

安装包不内置 Key —— 上一个版本把开发者的 Key 打进包里，任何人解压即可获取。
现在改成：**程序首次启动会弹出配置窗口**，粘 Key、点「保存并验证」即可开始用。

配置只存本机 `%LOCALAPPDATA%\XianyuTool\api_config.json`，不读取不打包不上传。

> `v1.3.4` ~ `v1.3.6` 的安装包都存在 Key 内嵌问题，相关安装包已从仓库删除。
> 如果你下载过这些版本，建议到智谱控制台重置 Key。

## 🖥️ 开箱即用：补齐三处会让别人电脑跑不起来的依赖

**1. 浏览器自动降级（最关键）**

PyInstaller 只打包 playwright 的 Node 驱动，不带 Chromium 本体（400MB+）。
程序默认只认 `%LOCALAPPDATA%\ms-playwright` 下的缓存，那是跑过
`playwright install` 才有的。普通用户没有，一启动就报 `Executable doesn't exist`。

现在自动回退到系统 Edge/Chrome（Win10/11 都自带）。
查找走三级：常见安装路径 → 注册表 App Paths → PATH。

**2. 打包 VC++ 运行库**

`cv2.pyd` 和 `python38.dll` 依赖 `vcruntime140 / vcruntime140_1 / msvcp140`，
没装 VC++ Redistributable 的电脑会报「缺少 vcruntime140.dll」。已随包分发。

**3. WebView2 依赖**

界面基于 WebView2（Win10 1803+ 自带）。老系统如提示缺少，装一下
[WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) 即可。

## 🔧 核心修复：去水印功能此前从未真正生效

两个独立问题叠加，导致这个功能一直是"假成功"：

1. **羽化混合公式写反**：中心区域贴回去的是**带水印的原图**，只有外圈 12 像素用了修复结果。
   水印区域高度超过 24 像素就完全去不掉。
2. **打包产物不含 torch / LaMa**：运行时加载失败，异常被吞掉，直接复制原图，
   但界面照常打印成功。

现已修复，并新增 **OpenCV 降级路径**——即使没有 LaMa 也能真正去水印。

## 🔒 安全修复

- 不再打包 `api_config.json` 与 `.py` 源码
- 修复 XSS：商品标题、卖家昵称、商品描述此前直接拼进 `innerHTML`。
  卖家昵称是第三方可控数据，构造 `<img onerror=...>` 即可调用本机程序接口
- 修复浏览器进程泄漏：5 处异常退出未释放 Chromium，第二次运行会卡死

## 🐛 其他修复

- **水印判定误判**：`'有' in answer` 把"没有水印"也判成有水印，进而误抹图片
- **水印检测漏检**：移除"首图无水印则全套跳过"的逻辑
- **V1 文案毁词**：删除单字替换规则（"哈哈"→"呀呀"、"哈尔滨"→"呀尔滨"）
- **违禁词未生效**：传了参数但没写进 prompt，AI 不知道哪些词不能用
- **每日限额失效**：输出清理误删 `request_count.json`，30 次/天形同虚设
- **emoji 清理残留零宽字符**：粘贴后显示乱码方块
- **保存文件崩溃**：选中源目录本身时抛 `SameFileError`
- **解析成功判定过松**：只有图片没有标题也算成功
- **顶部按钮被挤出视口**：新增按钮后 header 超宽，已改弹性布局

排除 PyQt5 / matplotlib / jedi / IPython / Pythonwin 等未使用的依赖，
